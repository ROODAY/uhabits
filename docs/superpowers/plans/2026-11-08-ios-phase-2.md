# iOS Phase 2 (organize + settings) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the iOS app Android Loop's organize features and settings. That covers categories, archive, reorder, sort, filter, search, skip and ? marks, a Settings screen, and dark mode, all with iPhone-style interactions.

**Architecture:** The Kotlin facade `LoopKit` (`uhabits-ios-kit`) gains list, sort, filter, preference, action, reorder and entry methods. Each one is built on the core's existing `HabitMatcher`, `HabitList` orders and commands, and is tested on the JVM. The facade returns a **flat list of header and habit rows**, the same model as Android's `HabitCardListAdapter`. SwiftUI renders those rows and reports gestures back as ids and indices. It does no list logic.

**Tech Stack:** Kotlin 2.3.20 Multiplatform (jvm + iosArm64 + iosSimulatorArm64), kotlin.test on JVM, SwiftUI (iOS 17), XcodeGen, GitHub Actions (`android-core`, `ios`).

**Spec:** `docs/superpowers/specs/2026-11-08-ios-phase-2-design.md` (parent: `docs/superpowers/specs/2026-11-06-ios-port-design.md`). Read both.

## Global Constraints

- Swift never computes habit logic or list logic: no sorting, filtering, grouping, search matching or drop math in Swift. Swift may reverse display order (C2) and lay out the history grid.
- No changes to `uhabits-android`. Avoid `uhabits-core` changes. If one becomes unavoidable, Android's behavior must stay identical and `android-core` must stay green.
- Every new public `LoopKit` method calls `refreshToday()` first, is annotated `@Throws(Exception::class)`, and has jvmTests in `uhabits-ios-kit/src/jvmTest/kotlin/org/isoron/uhabits/ioskit/`.
- Preferences use the core `Preferences` keys and defaults: `pref_short_toggle`, `pref_midnight_delay`, `pref_skip_enabled`, `pref_unknown_enabled`, `pref_checkmark_reverse_order`, `pref_first_weekday` (`-1` = system), `pref_default_order` (default `BY_POSITION`), `pref_default_secondary_order` (default `BY_NAME_ASC`), and `showArchived` / `showCompleted` via `Preferences.showArchived` / `.showCompleted`. **One exception:** short toggle reads as `true` when the key is unset (C1).
- All Swift DB access goes through `LoopStore` (`withKit` for reads, `mutate` for writes, so reminders get rescheduled and widgets reloaded). Respect `HabitListModel.isActive` and the close-when-inactive rule.
- Confirmations: only Delete asks, for one habit or several.
- Swift only compiles in CI. After each Swift task, push `feature/ios-port` and watch the `ios` workflow (`gh run watch -R ROODAY/uhabits`). Check the `screenshots` artifact for UI tasks. Never push `ios-v*` tags or run `testflight.yml`.
- Kotlin test command (Windows): `./gradlew :uhabits-ios-kit:jvmTest`. Before each Kotlin commit, also run `./gradlew :uhabits-core:jvmTest`.
- Commit signing follows the user's global CLAUDE.md: retry once, then commit unsigned with `git -c commit.gpgsign=false`. Don't push unsigned commits, and record the base SHA.

## Review Focus

1. **Hide completed with question marks on.** Android uses `isEnteredAllowed = showCompleted` instead of `isCompletedAllowed` when question marks are enabled. Without that, habits that have an entry but aren't completed would disappear. Pinned in Task 3.
2. **A stale drag.** The list refreshes (an external change signal, the midnight timer) between building the rows and the drop. The facade must notice that the habit isn't at `fromIndex` and do nothing, rather than moving the wrong habit. Pinned in Task 5.
3. **Dropping a habit right under a header, or at the very top.** It must take that header's category, or "" at the top, and be placed relative to the correct neighbour, the same way Android's `onDragEnd` does. Pinned in Task 5.
4. **Renaming a category to an existing category's name.** The two groups merge, and the list shows one header. Pinned in Task 4.
5. **First weekday "system default" (`-1`).** The resolved value must be 1 to 7 and drive both the core (weekly/monthly periods) and the Swift grid and picker. A raw `-1` must never reach Swift's layout. Pinned in Task 1.
